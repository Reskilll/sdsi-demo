PS2: Meeting Room Booking Engine

Office room-booking backend.

What your code is judged on

M1 Create, read, update and delete bookings (room, organiser, start, end, attendees).
M2 Reject overlapping bookings on the same room. Back-to-back bookings are allowed.
M3 Reject a booking when attendees exceed the room's capacity (input some sample rooms.json or similar).
M4 Find-slot: given a duration, attendee count and date, return the earliest free room and time between 09:00 and 18:00.
M5 Weekly recurring bookings, with conflicts reported per occurrence.
Also judged on: Functional correctness · Code quality and design · Testing · Documentation and runnability (README) · AI collaboration effectiveness (PROMPTS.md) · Security and robustness · Git hygiene · Performance awareness · Error handling and input validation

Your code is also checked against edge cases that aren’t listed here: think them through yourself.

Anything you build on top as a stretch or bonus also carries weight in your selection.
